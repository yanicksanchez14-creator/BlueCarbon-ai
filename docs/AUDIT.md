# v1 → v2: what was wrong and what changed

v1 (August 2025) was a first end-to-end attempt: a Streamlit + Earth Engine downloader, QGIS hand
labels for Mission Bay, and a small U-Net. v1 reported "94.23% accuracy". Re-evaluating the saved v1
weights on its own training chips gives **49% overall accuracy and 0.00 IoU for salt marsh**. The
94% figure could not be reproduced, and the setup below explains why it was never a meaningful number.

| # | v1 issue | Effect | v2 fix |
|---|---|---|---|
| 1 | Label `0` meant both *water* and *unlabeled* (rasterize `fill=0`) | ~67% of every chip was "water" by default; the model learned to predict water | `255` = ignore, excluded from loss and metrics (`schema.py`) |
| 2 | Overlapping chips (stride 128 on 256 px) + random train/val split | Neighbouring near-duplicate pixels in train *and* val → inflated scores | Non-overlapping chips, whole 5 km spatial blocks per split, fully held-out test sites (`tiling.py`) |
| 3 | Only 16 chips from one bay; ~3 validation chips | Accuracy measured on a few hundred thousand correlated pixels | 11 sites on 4 continents, fused global reference labels (`gee.py`) |
| 4 | Some labels generated by NDVI/NDWI thresholds (`make_labels_multiclass.py`) | The model learned to copy a formula it could compute from its own input bands | Labels from independent published products + optional survey polygons |
| 5 | Headline metric = pixel accuracy | Dominated by water; hides total failure on rare classes | Per-class IoU/F1, mIoU, macro-F1, κ; error-adjusted areas |
| 6 | No mangrove class; seagrass mapped at 0 ha | The core blue carbon habitats were missing | Six-class schema: water, mangrove, salt marsh, seagrass, tidal flat, other land |
| 7 | Exports in EPSG:4326 with a hard-coded "corrupted CRS" workaround | Areas computed from degrees; fragile | Everything in the local UTM zone, areas from the projected grid |
| 8 | `getDownloadURL` export | Fails above ~32 MB | Tiled `computePixels` download of any size |
| 9 | SCL cloud mask | Misses thin cloud / shadow | Cloud Score+ |
| 10 | Normalization stats in a separate `.npz` | Silent mismatch between train and inference | Stats, band list and class schema stored inside the checkpoint |
| 11 | Non-overlapping inference tiles | Seams at every 256 px | Overlapping tiles with Hann blending + flip TTA |
| 12 | Carbon: single point values, value computed from *standing stock* | False precision; standing stock isn't creditable | Tier 1 ranges, Monte Carlo 90% intervals, value from annual sequestration only |
| 13 | Hard-coded Windows paths, duplicate `old*.txt` scripts, no tests | Not reproducible | Installable package, CLI, YAML config, pytest + CI |

## Pilot data and the first U-Net pilot

The original Mission Bay hand labels are good data, just far too little of it. To keep them
useful, they were converted to the v2 schema:
v1 `seagrass → seagrass`, `saltmarsh → saltmarsh`, `upland`/`bare` → `other_land` (the "bare"
polygons covered all developed land), unlabeled → ignore. Unlabeled pixels with MNDWI > 0.25 and
NDVI < 0.05 became `water`.

Evaluated honestly with leave-one-block-out spatial cross-validation (4 folds × 2.56 km blocks,
pooled confusion in `data/pilot/cv_metrics.json`):

| | IoU |
|---|---|
| Open water | 0.92 |
| Other land | 0.95 |
| Salt marsh | 0.13 |
| Seagrass | 0.00 |
| **mIoU** | **0.50** (overall accuracy 0.94, κ 0.89) |

Water and land are easy. The blue carbon classes fail when the model is trained on a single
bay with a few thousand marsh pixels. That result motivated two fixes: a spectral model suited to small data (salt marsh 0.72, seagrass 0.52;
see `docs/EXPERIMENTS.md`), and multi-site training data (`notebooks/train_colab.ipynb`). Note that overall accuracy is 94% here too, while salt marsh
is almost entirely missed.
